# Aera editor direction

Mode: Operate. The requested Reference 1 defines a dark creative studio with soft rounded panels, pale-blue controls, smooth transitions, and glass surfaces. The sample slides carry the visual expression; the editor stays calm and consistent.

## First viewport

A slim navigation rail, a quiet document bar, and a three-column editor. A numbered slide navigator anchors the left. A large editorial cover occupies the center: pale stone, oversized DM Sans, an alpine photograph, and restrained Northstar sample branding. A right-hand inspector exposes four visual themes and actual design controls. A compact floating tool group sits inside the top of the canvas card and includes Ask Aera. The AI command field is hidden by default and opens as a glass overlay over the slide, with three specific suggestions. It does not take space from the slide. The slide has an 8px horizontal perimeter. Slide details and zoom share a bottom row; notes start collapsed under a labeled toggle. Side panels are slightly narrower to prioritize the width-limited slide.

## Signature interaction

The Ask Aera button toggles the floating AI input without resizing the slide; Escape and the close button dismiss it and restore focus. Live restyling: choosing a theme immediately changes the active slide and thumbnail. Applying the style to all slides updates the storyboard in one operation. The user can enter presentation mode and experience the same slide art at full scale.

## Motion grammar

State changes use 150–250ms transitions. Slide selection uses a short fade and 5px rise. Presentation transitions add a restrained blur. One thinking indicator signals simulated AI work. Reduced motion disables these effects.

## Responsive behavior

Below 1050px, the inspector becomes a drawer. Below 760px, the storyboard becomes a drawer, preserving a usable canvas. The asset library changes from three columns to horizontal image rows. Dialogs trap focus and close with Escape.

## Honesty and verification

AI interactions are clearly labeled preview simulations. Deck state is browser-local. Shared links open the demo, while JSON exports preserve edits. Automated TypeScript/build verification is required. Browser QA depends on the available preview infrastructure; the managed preview service was unavailable and automatic approval review blocked browser sign-in. A native publisher screenshot enabled desktop visual review; mobile and live interaction checks remain unverified.
